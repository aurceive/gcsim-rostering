# ui_server

Локальный интерфейс на основе KQM Sim и сервер для управления движками. Приложение
слушает только `127.0.0.1`; при первом открытии выбирается `gcsim`, затем выбор
сохраняется в браузере для адреса и порта страницы.

## Сборка и запуск

Нужны Git, Go, Node.js, Corepack и `tar`. Сабмодуль `engines/kqmsim` должен быть
инициализирован, а его отслеживаемые файлы — без несохранённых изменений.
Сборка использует зафиксированный в сабмодуле commit и не меняет его файлы.

```powershell
scripts\ui_server\bootstrap.ps1
apps\ui_server\ui_server.exe
```

Откройте `http://127.0.0.1:54320`. По умолчанию bootstrap собирает `server.exe`
и `gcsim.exe` (для балансера)
движка `gcsim`. Чтобы собрать серверы и CLI всех подключённых движков:

```powershell
scripts\ui_server\bootstrap.ps1 -Engine all
```

Чтобы оставить существующие бинарники движков без изменений, используйте
`-SkipEngines`; отдельно сервер и балансер можно собрать командой
`scripts\engines\build-engine-clis.ps1 -Engine kqmsim -Targets server,gcsim`.
Несобранный движок виден в списке, но выдаёт ошибку при запуске.

Параметры `ui_server.exe`: `-port` (54320), `-workers` (10),
`-timeout` (300 секунд), `-root` (путь к корню репозитория). Число workers и
timeout применяются к каждому серверу движка. Движки запускаются по запросу и
работают до завершения `ui_server`; на Windows они также завершаются при
аварийном завершении процесса благодаря Job Object. При переключении движка
уже запущенный расчёт и его sample остаются на исходном двигателе; чтобы
посмотреть его результат, выберите этот движок снова.

В списке также доступен `kqmsim (browser/WASM)` — исходный режим расчёта в
браузере. Он использует WebAssembly, собранный bootstrap из сабмодуля KQM, а не
локальный `server.exe`.

## Балансер

Кнопка Balancer передаёт текущий конфиг CLI выбранного движка и показывает
его stdout и stderr по мере работы. Рядом с кнопкой можно выбрать стандарт
балансировки; выбор сохраняется в браузере для адреса и порта страницы.
Это оптимизатор сабстатов KQM: сначала он подбирает восстановление энергии, затем
распределение остальных сабстатов для урона и уточняет компромисс между ними.
Вывод содержит этапы, промежуточные расчёты ER, итоговые строки статов,
предупреждения и ошибки; подробный режим `-v` не включён.

Используется тот же `-substatOptim`, который запускает `grow_roster` внутри
`-substatOptimFull`, но без дополнительной симуляции после оптимизации.
После успешного завершения конфиг заменяется, а окно вывода скрывается.
Если конфиг изменился во время работы или произошла ошибка, он не заменяется,
а окно остаётся открытым. При переключении движка работа продолжается в
исходном режиме; конфиг общий для всех режимов.

В режиме браузерного WebAssembly балансер запускает локальный CLI `kqmsim`,
поэтому для него тоже нужен `engines\bins\kqmsim\gcsim.exe`. Входной и
результирующий конфиги находятся во временной папке, удаляемой после работы;
доступный процесс отменяется при закрытии страницы или завершении сервера.

### Настройки стандартов

Стандарты находятся в `input\ui_server\ui_server.yaml`; bootstrap создаёт его
из `input\ui_server\examples\ui_server.example.yaml`, если файла ещё нет, и
не перезаписывает существующий файл. При ручной сборке скопируйте пример сами.
Настройки читаются при запуске сервера; после изменения файла перезапустите его.

```yaml
optimizer_variants:
  - name: kqms
    options: {}
  - name: custom
    options:
      talent_level: 9
      total_liquid_substats: 30
      indiv_liquid_cap: 12
      fixed_substats_count: 2
```

Названия должны быть непустыми и уникальными. Если список отсутствует или пуст,
доступен один вариант `kqms` с настройками движка по умолчанию. Вариант без
опций также использует настройки движка: обычно это 20 жидких сабстатов,
лимит 10 на один сабстат и 2 фиксированных. Можно указать также `fine_tune`,
`show_substat_scalars` и другие числовые опции, которые поддерживает выбранный
движок. Ключи опций содержат только строчные латинские буквы и подчёркивания;
числа должны быть неотрицательными. Количества и `fine_tune` — целые числа,
`show_substat_scalars` и `verbose` — 0 или 1. Неизвестные конкретному движку
опции приведут к ошибке оптимизатора.

Особая опция `talent_level` (целое число 1–10) задаёт все три таланта всех
персонажей отряда; эти изменения сохраняются в итоговом симконфиге. Если она
не указана, таланты не меняются. Она не передаётся движку как `-options`.
Ошибка настройки или отсутствующий ранее выбранный стандарт показывается
явно и блокирует балансировку до исправления; другие функции UI доступны.

Сборка сохраняет рабочую копию UI и зависимости в отдельной папке
`work\ui_server\build-<id>`; это игнорируемые временные файлы. Готовый UI
размещается в `apps\ui_server\web\dist` и тоже не коммитится.

## Внешние сервисы и ограничения

Публичные ссылки на результаты не создаются. Загрузка существующих ссылок
`/sh/<id>` и изображения используют KQM (`https://sim.kqm.gg`), поэтому для
них нужен интернет. Справочные ссылки KQM сохраняются. Сам расчёт локальный.
Серверы движков слушают только loopback, но их собственный CORS разрешает
обращения с других сайтов. Поэтому `ui_server` предназначен для доверенной
локальной среды; нельзя считать эти серверы защищёнными от страниц,
открытых в том же браузере.

UI использует справочники и редактор KQM. Другие движки могут поддерживать
другие конфиги, игровые данные и форматы результатов: совместимость нужно
проверять для конкретного движка и версии. KQM UI и наши его изменения
распространяются на условиях AGPL; исходная лицензия находится в
`engines/kqmsim/LICENSE`.

Хеш коммита результата показывается без ссылки: в зависимости от выбранного
движка он может относиться к другому репозиторию, а не к KQM.

Для проверки после сборки выполните `go -C apps\ui_server test ./...`.
Для интеграционного теста всех шести серверов сначала соберите их, затем
выполните:

```powershell
$env:UISERVER_INTEGRATION_ROOT = (Get-Location).Path
go -C apps\ui_server test .\internal\web -run TestRealEngines -count=1 -v
```

Для проверки балансеров замените `TestRealEngines` на `TestRealBalancers`.

Тесты адаптера ошибок интерфейса запускаются из папки `ui` последней сборки,
путь к которой выводит bootstrap:

```powershell
corepack pnpm --filter '@gcsim/components' exec vitest run src\Editor\Balancer.test.tsx src\Editor\ProviderValidation.test.tsx src\Editor\ExecutorProvider.test.tsx
```
